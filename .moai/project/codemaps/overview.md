# Stock Watchlist - 아키텍처 개요

## 시스템 아키텍처

```
┌─────────────────────────────────────────────────────────────────┐
│                         사용자 (브라우저)                        │
└────────────────────────────┬────────────────────────────────────┘
                             │ HTTP/HTTPS
                             ▼
┌─────────────────────────────────────────────────────────────────┐
│                    Next.js 애플리케이션                         │
│  ┌───────────────────────────────────────────────────────────┐ │
│  │  React Components (프론트엔드)                            │ │
│  │  - StockSearch, StockCard, WatchlistManager              │ │
│  │  - SWR으로 데이터 가져오기 및 캐싱                        │ │
│  └───────────────────────┬───────────────────────────────────┘ │
│                          │ fetch()                              │
│  ┌───────────────────────▼───────────────────────────────────┐ │
│  │  API Routes (백엔드)                                      │ │
│  │  - /api/stocks, /api/watchlist, /api/disclosures         │ │
│  └───────────────────────┬───────────────────────────────────┘ │
│                          │ child_process.spawn()               │
│  ┌───────────────────────▼───────────────────────────────────┐ │
│  │  Python 데이터 수집 스크립트                              │ │
│  │  - fetch_stock_data.py, fetch_all_stocks.py              │ │
│  │  - PyKRX, 네이버 금융 API, DART API 호출                  │ │
│  └───────────────────────────────────────────────────────────┘ │
└────────────────────────────┬────────────────────────────────────┘
                             │ Prisma Client
                             ▼
┌─────────────────────────────────────────────────────────────────┐
│                    PostgreSQL 데이터베이스                      │
│  - users, watchlists, stock_prices, news, disclosures         │
└─────────────────────────────────────────────────────────────────┘
```

## 설계 패턴

### 1. 계층형 아키텍처 (Layered Architecture)

```
프레젠테이션 계층 (React Components)
        ↓
비즈니스 로직 계층 (API Routes)
        ↓
데이터 액세스 계층 (Prisma ORM)
        ↓
데이터 저장소 (PostgreSQL)
```

### 2. API 게이트웨이 패턴
- Next.js API Routes가 내부 Python 스크립트와 외부 API 사이의 중개 역할

### 3. 리포지토리 패턴 (Prisma)
- 데이터베이스 접근 로직을 Prisma Client로 캡슐화

## 시스템 경계

### 외부 시스템 통합
- **PyKRX**: 한국거래소 공식 데이터 소스 (무료)
- **네이버 금융 API**: 실시간 주가 및 뉴스 데이터
- **DART API**: 전자공시시스템 정보

### 내부 시스템 경계
- **프론트엔드 ↔ 백엔드**: RESTful API (JSON)
- **백엔드 ↔ Python**: child_process 표준 입출력
- **백엔드 ↔ 데이터베이스**: Prisma ORM (PostgreSQL 프로토콜)

## 데이터 흐름

### 주식 검색 흐름
```
사용자 입력 → StockSearch.onSearch()
    → fetch('/api/stocks?q=삼성')
    → Python fetch_all_stocks.py 실행
    → PyKRX 전종목 데이터 쿼리
    → 결과 필터링 및 JSON 반환
    → API Route → 클라이언트
    → SWR 캐시 업데이트
    → UI 표시
```

### 관심종목 추가 흐름
```
사용자 종목 선택 → StockCard.onAdd()
    → fetch('/api/watchlist', POST)
    → API Route 검증
    → Prisma watchlist.create()
    → PostgreSQL 저장
    → 성공 응답
    → 페이지 새로고침
```

## 주요 기술적 결정

### 1. Python 스크립트 실행 방식
- **선택**: child_process.spawn()
- **이유**: PyKRX가 Python 전용 라이브러리
- **대안 고려**: Node.js 포트 (존재하지 않음), 별도 마이크로서비스

### 2. 데이터 캐싱 전략
- **선택**: SWR (클라이언트) + 메모리 캐시 (서버)
- **이유**: 불필요한 API 호출 감소
- **TTL**: 30초

### 3. 데이터베이스 선택
- **선택**: PostgreSQL
- **이유**: 관계형 데이터 모델, ACID 보장, Prisma 지원

### 4. UI 프레임워크
- **선택**: Next.js App Router + Tailwind CSS
- **이유**: 풀스택 개발 간소화, 서버 컴포넌트 성능 이점

## 확장 가능성

### 수직 확장 (Scale Up)
- 더 큰 데이터베이스 인스턴스
- 더 많은 메모리/CPU

### 수평 확장 (Scale Out)
- (계획) Redis 캐시 레이어 추가
- (계획) Python 스크립트를 별도 마이크로서비스로 분리
- (계획) CDN으로 정적 파일 제공

## 현재 제약사항

1. **Python 스크립트 실행**: 매 요청마다 새 프로세스 생성 (오버헤드)
2. **데이터베이스 풀링**: Prisma 기본 설정 (조정 필요 가능)
3. **API 속도 제한**: 외부 API 호출 제한으로 인한 대기 시간

## 향후 개선 계획

1. **마이크로서비스 분리**: Python 데이터 수집을 별도 서비스로
2. **메시지 큐**: 큐 기반 비동기 데이터 처리
3. **웹소켓**: 실시간 주가 업데이트
4. **로그인/인증**: 사용자별 개인화
