# SPEC-AUTH-002: 인수 기준

## 인수 테스트 시나리오

### AC-201: 로그인 Rate Limiting

#### 시나리오 1: 정상 로그인 시도 (Rate Limit 미적용)

**Given** 사용자가 로그인 페이지에 접속해 있다
**When** 올바른 이메일과 비밀번호로 로그인을 시도한다
**Then** 로그인이 성공하고 메인 대시보드로 리다이렉트된다
**And** Rate Limit 카운터가 증가하지 않는다 (실패 시에만 카운트)

#### 시나리오 2: 연속 로그인 실패 후 Rate Limit 활성화

**Given** 동일한 IP 주소와 이메일 조합으로 4회 연속 로그인에 실패했다
**When** 5분 이내에 5번째 로그인 실패가 발생한다
**Then** 시스템은 429 Too Many Requests 상태 코드를 반환한다
**And** 응답 본문에 `{ success: false, error: "잠시 후 다시 시도해주세요", retryAfter: <남은초> }` 형식이 포함된다
**And** `Retry-After` 헤더에 남은 시간(초)이 설정된다

#### 시나리오 3: Rate Limit 만료 후 재시도

**Given** Rate Limit이 활성화되어 5분이 경과했다
**When** 사용자가 다시 로그인을 시도한다
**Then** 카운터가 초기화되어 새로운 시도가 허용된다

#### 시나리오 4: 다른 이메일은 독립적

**Given** `user1@test.com`에 대해 Rate Limit이 활성화되어 있다
**When** 동일 IP에서 `user2@test.com`으로 로그인을 시도한다
**Then** Rate Limit에 영향을 받지 않고 정상 처리된다

### AC-202: 회원가입 Rate Limiting

#### 시나리오 1: 정상 회원가입 (Rate Limit 미적용)

**Given** 사용자가 회원가입 페이지에 접속해 있다
**When** 유효한 이메일과 12자 이상 비밀번호로 회원가입을 시도한다
**Then** 회원가입이 성공하고 자동 로그인된다

#### 시나리오 2: 다수 회원가입 시도 후 Rate Limit

**Given** 동일한 IP 주소에서 1시간 이내에 3회 회원가입을 시도했다
**When** 4번째 회원가입을 시도한다
**Then** 429 Too Many Requests 상태 코드가 반환된다
**And** 응답 본문에 남은 시간 정보가 포함된다

#### 시나리오 3: 다른 IP는 독립적

**Given** IP 192.168.1.1에서 Rate Limit이 활성화되어 있다
**When** IP 192.168.1.2에서 회원가입을 시도한다
**Then** Rate Limit에 영향을 받지 않는다

---

### AC-203: Rate Limit 응답 형식

#### 시나리오: Rate Limit 활성 시 응답

**Given** Rate Limit이 활성 상태이다
**When** 제한된 엔드포인트에 요청을 보낸다
**Then** HTTP 상태 코드 429가 반환된다
**And** `Retry-After` 헤더가 존재한다
**And** 응답 본문 JSON에 `retryAfter` 필드가 포함된다
**And** 에러 메시지는 "잠시 후 다시 시도해주세요"이다

---

### AC-204: 이메일 열거 방지

#### 시나리오 1: 신규 이메일 회원가입 (정상)

**Given** 가입되지 않은 이메일 `new@example.com`이 있다
**When** 회원가입 API에 해당 이메일로 요청을 보낸다
**Then** 201 Created 상태 코드가 반환된다
**And** 새 User 레코드가 생성된다
**And** 응답에 이메일 정보가 포함된다

#### 시나리오 2: 중복 이메일 회원가입 (핵심 시나리오)

**Given** 이미 가입된 이메일 `existing@example.com`이 있다
**When** 회원가입 API에 동일한 이메일로 요청을 보낸다
**Then** 200 OK 상태 코드가 반환된다 (409 Conflict 아님)
**And** 새 User 레코드는 생성되지 않는다
**And** 응답이 정상 가입 응답과 유사한 형식이다
**And** 서버 로그에 보안 이벤트로 기록된다

#### 시나리오 3: 중복 이메일 응답 비교

**Given** 공격자가 이메일 열거를 시도한다
**When** 미가입 이메일과 기가입 이메일로 각각 회원가입 요청을 보낸다
**Then** 두 응답의 상태 코드가 동일하다 (200/201)
**And** 두 응답의 형식이 유사하여 계정 존재 여부를 구분할 수 없다

### AC-205: 비밀번호 최소 길이

#### 시나리오 1: 12자 미만 비밀번호 거부

**Given** 사용자가 회원가입 폼에 접속해 있다
**When** 11자 비밀번호를 입력하고 회원가입을 시도한다
**Then** 서버가 400 Bad Request를 반환한다
**And** 오류 메시지에 "비밀번호는 12자 이상이어야 합니다"가 포함된다

#### 시나리오 2: 정확히 12자 비밀번호 허용

**Given** 사용자가 회원가입 폼에 접속해 있다
**When** 정확히 12자 비밀번호를 입력하고 회원가입을 시도한다
**Then** 복잡성 요구사항을 충족하면 회원가입이 진행된다

---

### AC-206: 비밀번호 문자 종류 검증

#### 시나리오 1: 2종류 문자만 포함 (거부)

**Given** 비밀번호 "abcdefgh1234" (소문자+숫자, 2종류)를 입력한다
**When** 회원가입을 시도한다
**Then** 400 Bad Request가 반환된다
**And** 오류 메시지에 부족한 종류가 안내된다

#### 시나리오 2: 3종류 문자 포함 (허용)

**Given** 비밀번호 "Abcdefgh1234" (대문자+소문자+숫자, 3종류)를 입력한다
**When** 회원가입을 시도한다
**Then** 회원가입이 정상 진행된다

#### 시나리오 3: 4종류 문자 포함 (허용)

**Given** 비밀번호 "Abcdefgh123!" (대문자+소문자+숫자+특수문자, 4종류)를 입력한다
**When** 회원가입을 시도한다
**Then** 회원가입이 정상 진행된다

#### 시나리오 4: 종류별 부족 안내

**Given** 비밀번호 "abcdefghijkl" (소문자만, 1종류)를 입력한다
**When** 회원가입을 시도한다
**Then** 오류 메시지에 "대문자, 숫자, 특수문자 중 2가지 이상 추가해주세요"와 같이 구체적인 안내가 포함된다

---

### AC-207: 비밀번호 강도 실시간 평가

#### 시나리오 1: 약한 비밀번호

**Given** 사용자가 회원가입 폼의 비밀번호 필드에 입력 중이다
**When** "password" 또는 "12345678"을 입력한다
**Then** 강도 표시기가 "약"으로 표시된다 (빨간색)

#### 시나리오 2: 보통 비밀번호

**Given** 사용자가 비밀번호 필드에 입력 중이다
**When** "Mypassword1"을 입력한다
**Then** 강도 표시기가 "보통"으로 표시된다 (노란색)

#### 시나리오 3: 강한 비밀번호

**Given** 사용자가 비밀번호 필드에 입력 중이다
**When** "K#9mPx!vL2wQ"를 입력한다
**Then** 강도 표시기가 "강" 또는 "매우 강"으로 표시된다 (초록색)

## 에지 케이스 테스트 시나리오

### EC-001: Rate Limit 경계값

| 케이스 | 입력 | 기대 결과 |
|--------|------|-----------|
| 4회 실패 후 성공 | 4회 실패 → 올바른 비밀번호 | 5번째 시도 성공 (카운터 4) |
| 5회 실패 후 추가 시도 | 5회 실패 → 6번째 시도 | 429 응답 |
| 4:59에 5회 실패, 5:01에 시도 | 시간 만료 후 | 새 윈도우로 카운터 리셋 |
| 동시 다발적 요청 | 10개 동시 요청 | 5개만 허용, 5개는 429 |

### EC-002: 비밀번호 경계값

| 케이스 | 입력 | 기대 결과 |
|--------|------|-----------|
| 11자, 3종류 | "Abcd1234xyz" (11자) | 거부 (길이 부족) |
| 12자, 2종류 | "abcdefghijkl" (12자, 소문자만) | 거부 (종류 부족) |
| 12자, 3종류 | "Abcdefgh1234" (12자, 3종류) | 허용 |
| 100자, 4종류 | 매우 긴 비밀번호 | 허용 (최대 길이 제한 없음) |
| 유니코드 포함 | "한글Password1!" | 허용 (유니코드는 특수문자로 분류) |
| 공백 포함 | "My Pass word1!" | 허용 (공백은 특수문자로 분류) |

### EC-003: Rate Limit 메모리 관리

| 케이스 | 조건 | 기대 결과 |
|--------|------|-----------|
| 만료 엔트리 정리 | 1분 경과 후 | 만료된 엔트리가 Map에서 제거됨 |
| 최대 엔트리 초과 | 10,001개 키 생성 | 가장 오래된 엔트리가 제거됨 |
| PM2 재시작 | 프로세스 재시작 | 모든 Rate Limit 상태 초기화 |

### EC-004: 이메일 열거 방지

| 케이스 | 입력 | 기대 결과 |
|--------|------|-----------|
| 대소문자 변형 | existing@example.com vs Existing@example.com | 이메일 비교는 대소문자 무시, 동일한 200 응답 |
| 연속 시도 | 동일 이메일 5회 연속 가입 시도 | 200 OK 5회 (Rate Limit 별도 적용) |
| 서버 로그 | 중복 이메일 시도 | 보안 이벤트로 로그 기록됨 |

### EC-005: 기존 사용자 영향

| 케이스 | 조건 | 기대 결과 |
|--------|------|-----------|
| 8자 비밀번호 로그인 | 기존 8자 비밀번호 사용자 | 정상 로그인 (소급적용 없음) |
| 비밀번호 변경 없음 | 기존 사용자 | 강제 비밀번호 변경 요구 없음 |
